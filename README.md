# django-orm

Учебный Django-проект: витрина товаров (каталог), обратная связь, блог с CRUD, админка. У товаров есть **владелец** (`owner`) и **публикация в каталоге** (`is_published`); модераторы настраиваются группой Django **«Модератор продуктов»** (права на снятие с публикации и удаление любого товара). Записи блога для группы **«Контент-менеджер»** — по стандартным правам `blog.*`. Управление товарами через формы с валидацией (запрещённые слова, цена, загрузка изображений). Poetry, тесты (pytest), Ruff.

## Стек

- **Python** 3.10+
- **Django** 5.x
- **БД:** PostgreSQL (основной вариант, если в `.env` задан `DB_NAME`) или SQLite (`db.sqlite3`), если `DB_NAME` не задан — запасной вариант без Postgres
- **Медиа:** Pillow (превью блога, фото товаров)
- **Стили:** Bootstrap 5, кастомный CSS в `catalog/static/catalog/`

## Установка и окружение

```bash
poetry install
cp .env.example .env   # при необходимости отредактируйте значения
```

## База данных

### PostgreSQL (рекомендуется)

1. Установите и запустите PostgreSQL (например через Homebrew на macOS).
2. Создайте пользователя и базу (пример в `.env.example`).
3. В `.env` укажите `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`.
4. Примените миграции: `poetry run python manage.py migrate`.

Для **тестов** Django создаёт отдельную БД с префиксом `test_`; пользователь PostgreSQL должен иметь право её создавать (`CREATEDB` или суперпользователь).

### SQLite (запасной вариант)

Если Postgres недоступен, **удалите или закомментируйте `DB_NAME`** (и при необходимости строки `DB_USER` / `DB_PASSWORD` / …) в `.env`. Тогда используется файл **`db.sqlite3`** в корне проекта. Затем снова `poetry run python manage.py migrate`.

Тесты в этом режиме тоже идут в SQLite (отдельная тестовая БД создаётся автоматически).

## Локальный сервер

```bash
poetry run python manage.py migrate
poetry run python manage.py setup_catalog_groups   # группы «Модератор продуктов» и «Контент-менеджер»
poetry run python manage.py runserver 8080
```

- Сайт: http://127.0.0.1:8080/
- Админка: http://127.0.0.1:8080/admin/

Создайте суперпользователя для входа в админку (назначение групп и полный доступ):

```bash
poetry run python manage.py createsuperuser
```

**Демо-пользователи** для проверки прав (после миграций и `setup_catalog_groups`):

```bash
poetry run python manage.py seed_demo_users
```

Логины: `demo_owner`, `demo_moderator`, `demo_content`, `demo_plain`; пароль у всех: `DemoPass1!`. Команда выводит URL черновика и опубликованного товара.

### Быстрая проверка маршрутов (curl)

После `runserver 8080` ожидаемые коды: публичные страницы — **200**, CRUD без сессии — **302** на `/accounts/login/`.

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/              # главная
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/catalog/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/contacts/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/blogs/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/product/manage/  # 302
curl -sI http://127.0.0.1:8080/product/manage/ | grep -i location              # next=/product/manage/
```

В браузере: **Регистрация** (`/accounts/register/`) или **Вход** (`/accounts/login/`), затем **Товары (CRUD)** и **Блог**; форма **Контакты** с валидными и невалидными данными. Суперпользователь по-прежнему нужен для входа в `/admin/`.

## Функционал по разделам

### Приложение `catalog` (магазин)

| URL | Описание |
|-----|----------|
| `/` | **Главная** — до 5 последних опубликованных товаров (`is_published=True`), логирование в `logs/catalog_views.log`. |
| `/catalog/` | **Каталог** — список опубликованных товаров, фильтры по категории и диапазону цены, сортировка. |
| `/category/` | Первая категория и её опубликованные товары. |
| `/category/<id>/` | Категория по id и её опубликованные товары. |
| `/product/<id>/` | **Карточка товара** — фото, цена, описание, категория, владелец, даты. **Черновик** (`is_published=False`) по прямой ссылке доступен только **владельцу** и пользователям с правами модератора; остальным — 404. Ссылки «Редактировать» / «Удалить» — по правилам владельца и модератора (см. ниже). |
| `/contacts/` | **Обратная связь** — форма (`ModelForm`): имя, email, сообщение. Ошибки валидации показываются на странице. После успешной отправки — сообщение об успехе; **список обращений на сайте не публикуется** (данные в админке). |
| `/accounts/register/` | **Регистрация** нового пользователя (логин, опционально email, пароль ×2). После успеха — автоматический вход и редирект на главную. |
| `/accounts/login/` | **Вход** на сайт (не админка). Поддерживается параметр `?next=` для возврата на защищённую страницу. |
| `/accounts/logout/` | **Выход** (POST из меню пользователя). |
| `/product/manage/` | **Управление товарами** — таблица с просмотром / правкой / удалением; **модератор** видит все товары, остальные авторизованные — **только свои**. Кнопки публикации / снятия с публикации — у модератора (POST). |
| `/product/add/` | **Создание товара** — форма карточки **без** поля публикации; `owner` подставляется автоматически. **Только для авторизованных.** |
| `/product/<id>/edit/` | **Редактирование** — **только владелец** товара. |
| `/product/<id>/delete/` | **Удаление** — **владелец** или пользователь с правом `catalog.delete_product` (группа модератора). |
| `/product/<id>/publish/` | **Публикация** в каталог (POST, CSRF) — право `catalog.can_unpublish_product`. |
| `/product/<id>/unpublish/` | **Снятие с публикации** (POST) — то же право `can_unpublish_product`. |

**Публикация в каталоге** (`is_published`): задаётся модератором через POST-действия; в форме редактирования товара поля публикации нет. Неопубликованные позиции не показываются в каталоге, на главной и в категориях; доступ к карточке черновика — только владельцу и модераторам.

**Валидация формы товара (`ProductForm`):**

- Запрещённые подстроки в **наименовании** и **описании** (отдельные методы `clean_name` / `clean_description`), без учёта регистра.
- Список задаётся **без правки Python**: файл `config/forbidden_product_words.txt` (по умолчанию) или переменные окружения `PRODUCT_FORBIDDEN_WORDS_FILE` / `PRODUCT_FORBIDDEN_WORDS` (см. `.env.example`).
- **Цена** не может быть отрицательной (`clean_price`, `ValidationError`).
- **Изображение** (опционально): только JPEG/PNG, до 5 МБ (`config/image_validation.py`).

В меню сайта есть пункт **«Товары (CRUD)»** — ведёт на управление списком (с редиректом на вход, если не авторизованы).

### Приложение `blog`

| URL | Описание |
|-----|----------|
| `/blogs/` | Список **опубликованных** записей. |
| `/blogs/<id>/` | Статья; счётчик просмотров увеличивается при открытии. |
| `/blogs/create/` | Создание записи (форма с превью). Право `blog.add_blogpost` (группа **«Контент-менеджер»** или суперпользователь); без права — 403 после входа. |
| `/blogs/<id>/edit/` | Редактирование — `blog.change_blogpost`. |
| `/blogs/<id>/delete/` | Удаление — `blog.delete_blogpost`. |

Гостям показывается ссылка «Войти, чтобы создавать записи»; ссылки на создание/редактирование/удаление в шаблонах — по `perms.blog.*`. Превью валидируется так же по типу и размеру, как изображение товара.

### Админка

Регистрация моделей: категории, товары (в т.ч. `owner`, `is_published`), контакты, записи блога.

### Авторизация и права

- **Товары:** вход обязателен для списка управления, создания и правок; дополнительно **миксины** проверяют владельца и право на удаление; публикация — `PermissionRequiredMixin` с `catalog.can_unpublish_product`.
- **Блог:** создание/изменение/удаление — `PermissionRequiredMixin` с соответствующими правами `blog.*`.
- `LOGIN_URL` — **`catalog:login`** (`/accounts/login/`). Регистрация: `/accounts/register/`.
- Группы и права в БД: **`python manage.py setup_catalog_groups`**. Загрузка демо-данных каталога: **`load_catalog`** (при пустой БД может подтянуть фикстуру пользователя `catalog_user.json`).
- Админка (`/admin/`) — назначение групп пользователям и полный доступ у суперпользователя.

## Тесты и качество кода

Запуск такой же, как для приложения: при настройке на PostgreSQL сервер должен быть доступен; в режиме SQLite (без `DB_NAME`) — достаточно файловой БД.

```bash
poetry run pytest

poetry run python manage.py test
```

```bash
poetry run ruff check .

```

## Шаблоны и статика

- **Базовый шаблон:** `catalog/templates/catalog/base.html` — сайдбар, меню, переключение темы, вывод flash-сообщений.
- **Статика:** `catalog/static/catalog/` (CSS, JS, изображения), Bootstrap 5 с CDN в базовом шаблоне.

Референсный прототип **web_app** не входит в репозиторий; визуальная логика перенесена в приложение `catalog`.

```bash
poetry run python manage.py makemigrations
```
