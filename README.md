# django-orm

Учебный Django-проект: витрина товаров (каталог), обратная связь, блог с CRUD, админка. Управление товарами через формы с валидацией (запрещённые слова, цена, загрузка изображений). Регистрация и вход вынесены в приложение **`users`**: кастомная модель пользователя с **входом по email**, опциональное редактирование профиля (телефон, страна, аватар). Poetry, тесты (pytest), Ruff.

**Вики:** [docs/wiki/README.md](docs/wiki/README.md) — архитектура проекта и отчёт по [безопасности](docs/wiki/security.md).

## Стек

- **Python** 3.10+
- **Django** 5.x
- **БД:** PostgreSQL (основной вариант, если в `.env` задан `DB_NAME`) или SQLite (`db.sqlite3`), если `DB_NAME` не задан — запасной вариант без Postgres
- **Медиа:** Pillow (превью блога, фото товаров)
- **Стили:** Bootstrap 5, кастомный CSS в `catalog/static/catalog/`
- **Кеширование:** Redis (`django.core.cache.backends.redis.RedisCache`), управляется через `CACHE_ENABLED` в `.env`
- **Пользователи:** `AUTH_USER_MODEL = users.User` (`USERNAME_FIELD = email`), маршруты под префиксом `/accounts/`

## Установка и окружение

```bash
poetry install
cp .env.example .env   # при необходимости отредактируйте значения
```

В `.env` можно задать **SMTP** (`EMAIL_HOST`, `EMAIL_HOST_USER`, …) — после регистрации отправляется приветственное письмо; при ошибке доставки регистрация не отменяется (ошибка пишется в лог).

## Redis и кеширование

Для кеширования используется **Redis**. Установка (macOS):

```bash
brew install redis
redis-server            # запустить сервер
redis-cli ping          # ожидаем PONG
```

В `.env` задайте:

```
CACHE_ENABLED=True
REDIS_URL=redis://127.0.0.1:6379/1
```

При `CACHE_ENABLED=False` (или если переменная не задана) кеширование отключено — приложение работает без Redis.

**Что кешируется:**

- **Страница карточки товара** — `cache_page` (серверный кеш, 15 мин).
- **Список товаров в категории** — низкоуровневое кеширование в сервисной функции `get_products_by_category` (`cache.get` / `cache.set`, 15 мин).

## База данных

### PostgreSQL (рекомендуется)

1. Установите и запустите PostgreSQL (например через Homebrew на macOS).
2. Создайте пользователя и базу (пример в `.env.example`).
3. В `.env` укажите `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`.
4. Примените миграции: `poetry run python manage.py migrate`.

Для **тестов** Django создаёт отдельную БД с префиксом `test_`; пользователь PostgreSQL должен иметь право её создавать (`CREATEDB` или суперпользователь).

### SQLite (запасной вариант)

Если Postgres недоступен, **удалите или закомментируйте `DB_NAME`** (и при необходимости строки `DB_USER` / `DB_PASSWORD` / …) в `.env`. Тогда используется файл **`db.sqlite3`** в корне проекта. Затем снова `poetry run python manage.py migrate`.

Тесты в этом режиме тоже идут в SQLite (отдельная тестовая БД создаётся автоматически).

## Локальный сервер

```bash
poetry run python manage.py runserver 8080
```

- Сайт: http://127.0.0.1:8080/
- Админка: http://127.0.0.1:8080/admin/

Создайте суперпользователя для входа в админку и для доступа к CRUD товаров и блога на сайте. У модели пользователя логином служит **email** — команда запросит адрес электронной почты и пароль (и при необходимости имя):

```bash
poetry run python manage.py createsuperuser
```

### Быстрая проверка маршрутов (curl)

После `runserver 8080` ожидаемые коды: публичные страницы (главная, каталог, контакты, список блога) — **200**; **карточка товара** и CRUD без сессии — **302** на `/accounts/login/`.

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/              # главная
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/catalog/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/contacts/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/blogs/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/product/1/       # 302 (нужен вход)
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/product/manage/  # 302
curl -sI http://127.0.0.1:8080/product/manage/ | grep -i location              # next=/product/manage/
```

В браузере: **Регистрация** (`/accounts/register/`) или **Вход** (`/accounts/login/`), затем **Товары (CRUD)** и **Блог**; форма **Контакты** с валидными и невалидными данными. Суперпользователь по-прежнему нужен для входа в `/admin/`.

## Функционал по разделам

### Приложение `catalog` (магазин)

| URL | Описание |
|-----|----------|
| `/` | **Главная** — до 5 последних опубликованных товаров (`is_published=True`), логирование в `logs/catalog_views.log`. |
| `/catalog/` | **Каталог** — список опубликованных товаров, фильтры по категории и диапазону цены, сортировка. |
| `/category/` | Первая категория и её опубликованные товары. |
| `/category/<id>/` | Категория по id и её опубликованные товары. |
| `/product/<id>/` | **Карточка товара** — фото, цена, описание, категория, даты; ссылки «Редактировать», «Удалить», «Все товары». **Только для авторизованных** (`LoginRequiredMixin`); гость перенаправляется на вход с `?next=`. |
| `/contacts/` | **Обратная связь** — форма (`ModelForm`): имя, email, сообщение. Ошибки валидации показываются на странице. После успешной отправки — сообщение об успехе; **список обращений на сайте не публикуется** (данные в админке). |
| `/product/manage/` | **Список всех товаров** для управления (таблица, ссылки просмотр / правка / удаление). **Только для авторизованных.** |
| `/product/add/` | **Создание товара** — форма со всеми полями карточки. **Только для авторизованных.** |
| `/product/<id>/edit/` | **Редактирование товара**. **Только для авторизованных.** |
| `/product/<id>/delete/` | **Подтверждение и удаление** товара. **Только для авторизованных.** |

**Поле «Показывать в каталоге»** (`is_published`): скрытые товары не попадают на главную, в каталог и в списки категорий, но остаются в «Управление товарами»; карточку по прямой ссылке может открыть **вошедший** пользователь (гость будет перенаправлен на вход).

**Валидация формы товара (`ProductForm`):**

- Запрещённые подстроки в **наименовании** и **описании** (отдельные методы `clean_name` / `clean_description`), без учёта регистра.
- Список задаётся **без правки Python**: файл `config/forbidden_product_words.txt` (по умолчанию) или переменные окружения `PRODUCT_FORBIDDEN_WORDS_FILE` / `PRODUCT_FORBIDDEN_WORDS` (см. `.env.example`).
- **Цена** не может быть отрицательной (`clean_price`, `ValidationError`).
- **Изображение** (опционально): только JPEG/PNG, до 5 МБ (`config/image_validation.py`).

В меню сайта есть пункт **«Товары (CRUD)»** — ведёт на управление списком (с редиректом на вход, если не авторизованы).

### Приложение `blog`

| URL | Описание |
|-----|----------|
| `/blogs/` | Список **опубликованных** записей. |
| `/blogs/<id>/` | Статья; счётчик просмотров увеличивается при открытии. |
| `/blogs/create/` | Создание записи (форма с превью). **Только для авторизованных.** |
| `/blogs/<id>/edit/` | Редактирование. **Только для авторизованных.** |
| `/blogs/<id>/delete/` | Удаление с подтверждением. **Только для авторизованных.** |

Гостям показывается ссылка «Войти, чтобы создавать записи» (ведёт на **`users:login`**). Превью валидируется так же по типу и размеру, как изображение товара.

### Приложение `users` (аккаунты на сайте)

| URL | Описание |
|-----|----------|
| `/accounts/register/` | **Регистрация** — email, пароль и подтверждение. После успеха — автоматический вход, редирект на главную, попытка отправить приветственное письмо (см. SMTP в `.env`). |
| `/accounts/login/` | **Вход** по email и паролю (не админка). Параметр `?next=` возвращает на запрошенную страницу после авторизации. |
| `/accounts/logout/` | **Выход** — только **POST** (кнопка в меню пользователя). |
| `/accounts/profile/` | **Профиль** — имя, фамилия, телефон, страна, аватар. **Только для авторизованных.** |

Шаблоны и формы лежат в `users/`; в меню сайта отображается email (или короткое имя) и выпадающий блок «Профиль» / «Выход».

### Админка

Регистрация моделей: **пользователи** (`users.User`), категории, товары (в т.ч. `is_published`), контакты, записи блога.

### Авторизация на сайте

Просмотр **карточки товара**, CRUD товаров и CRUD блога (кроме публичного списка и чтения статей) защищены `LoginRequiredMixin`. `LOGIN_URL` = **`users:login`** (`/accounts/login/`). `LOGIN_REDIRECT_URL` и `LOGOUT_REDIRECT_URL` ведут на главную каталога. Админка (`/admin/`) — отдельный вход и права; суперпользователь и обычный пользователь сайта различаются стандартно для Django.

**Замечание по URL:** список блога открывается по **`/blogs/`** (с буквой **s** и завершающим слэшем); путь `/blog/` в проекте не зарегистрирован.

## Шаблоны и статика

- **Базовый шаблон:** `catalog/templates/catalog/base.html` — сайдбар, меню, переключение темы, блок пользователя (вход / регистрация или профиль / выход), вывод flash-сообщений.
- **Шаблоны `users`:** `users/templates/users/` (регистрация, вход, профиль).
- **Статика:** `catalog/static/catalog/` (CSS, JS, изображения), Bootstrap 5 с CDN в базовом шаблоне.

Референсный прототип **web_app** не входит в репозиторий; визуальная логика перенесена в приложение `catalog`.
