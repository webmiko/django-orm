# django-orm

Учебный Django-проект: витрина товаров (каталог), обратная связь, блог с CRUD, админка. Управление товарами через формы с валидацией (запрещённые слова, цена, загрузка изображений). Poetry, тесты (pytest), Ruff.

## Стек

- **Python** 3.10+
- **Django** 5.x
- **БД:** PostgreSQL (рекомендуется для разработки по заданию) или SQLite, если переменная `DB_NAME` в `.env` не задана
- **Медиа:** Pillow (превью блога, фото товаров)
- **Стили:** Bootstrap 5, кастомный CSS в `catalog/static/catalog/`

## Установка и окружение

```bash
poetry install
cp .env.example .env   # при необходимости отредактируйте значения
```

## База данных

### PostgreSQL

1. Установите и запустите PostgreSQL (например через Homebrew на macOS).
2. Создайте пользователя и базу (пример в `.env.example`).
3. В `.env` укажите `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`.
4. Примените миграции:

```bash
poetry run python manage.py migrate
```

### SQLite (быстрый старт без PostgreSQL)

Удалите или закомментируйте `DB_NAME` в `.env` (или не задавайте её). Django создаст файл `db.sqlite3` в корне проекта.

```bash
poetry run python manage.py migrate
```

## Локальный сервер

```bash
poetry run python manage.py runserver 8080
```

- Сайт: http://127.0.0.1:8080/
- Админка: http://127.0.0.1:8080/admin/

Создайте суперпользователя для входа в админку и для доступа к CRUD товаров и блога на сайте:

```bash
poetry run python manage.py createsuperuser
```

### Быстрая проверка маршрутов (curl)

После `runserver 8080` ожидаемые коды: публичные страницы — **200**, CRUD без сессии — **302** на `/accounts/login/`.

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/              # главная
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/catalog/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/contacts/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/blogs/
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8080/product/manage/  # 302
curl -sI http://127.0.0.1:8080/product/manage/ | grep -i location              # next=/product/manage/
```

В браузере: **Регистрация** (`/accounts/register/`) или **Вход** (`/accounts/login/`), затем **Товары (CRUD)** и **Блог**; форма **Контакты** с валидными и невалидными данными. Суперпользователь по-прежнему нужен для входа в `/admin/`.

## Функционал по разделам

### Приложение `catalog` (магазин)

| URL | Описание |
|-----|----------|
| `/` | **Главная** — до 5 последних опубликованных товаров (`is_published=True`), логирование в `logs/catalog_views.log`. |
| `/catalog/` | **Каталог** — список опубликованных товаров, фильтры по категории и диапазону цены, сортировка. |
| `/category/` | Первая категория и её опубликованные товары. |
| `/category/<id>/` | Категория по id и её опубликованные товары. |
| `/product/<id>/` | **Карточка товара** — фото, цена, описание, категория, даты. Для **вошедшего** пользователя — ссылки «Редактировать», «Удалить», «Все товары». |
| `/contacts/` | **Обратная связь** — форма (`ModelForm`): имя, email, сообщение. Ошибки валидации показываются на странице. После успешной отправки — сообщение об успехе; **список обращений на сайте не публикуется** (данные в админке). |
| `/accounts/register/` | **Регистрация** нового пользователя (логин, опционально email, пароль ×2). После успеха — автоматический вход и редирект на главную. |
| `/accounts/login/` | **Вход** на сайт (не админка). Поддерживается параметр `?next=` для возврата на защищённую страницу. |
| `/accounts/logout/` | **Выход** (POST из меню пользователя). |
| `/product/manage/` | **Список всех товаров** для управления (таблица, ссылки просмотр / правка / удаление). **Только для авторизованных.** |
| `/product/add/` | **Создание товара** — форма со всеми полями карточки. **Только для авторизованных.** |
| `/product/<id>/edit/` | **Редактирование товара**. **Только для авторизованных.** |
| `/product/<id>/delete/` | **Подтверждение и удаление** товара. **Только для авторизованных.** |

**Поле «Показывать в каталоге»** (`is_published`): скрытые товары не попадают на главную, в каталог и в списки категорий, но остаются в «Управление товарами» и открываются по прямой ссылке на карточку.

**Валидация формы товара (`ProductForm`):**

- Запрещённые подстроки в **наименовании** и **описании** (отдельные методы `clean_name` / `clean_description`), без учёта регистра.
- Список задаётся **без правки Python**: файл `config/forbidden_product_words.txt` (по умолчанию) или переменные окружения `PRODUCT_FORBIDDEN_WORDS_FILE` / `PRODUCT_FORBIDDEN_WORDS` (см. `.env.example`).
- **Цена** не может быть отрицательной (`clean_price`, `ValidationError`).
- **Изображение** (опционально): только JPEG/PNG, до 5 МБ (`config/image_validation.py`).

В меню сайта есть пункт **«Товары (CRUD)»** — ведёт на управление списком (с редиректом на вход, если не авторизованы).

### Приложение `blog`

| URL | Описание |
|-----|----------|
| `/blogs/` | Список **опубликованных** записей. |
| `/blogs/<id>/` | Статья; счётчик просмотров увеличивается при открытии. |
| `/blogs/create/` | Создание записи (форма с превью). **Только для авторизованных.** |
| `/blogs/<id>/edit/` | Редактирование. **Только для авторизованных.** |
| `/blogs/<id>/delete/` | Удаление с подтверждением. **Только для авторизованных.** |

Гостям показывается ссылка «Войти, чтобы создавать записи». Превью валидируется так же по типу и размеру, как изображение товара.

### Админка

Регистрация моделей: категории, товары (в т.ч. `is_published`), контакты, записи блога.

### Авторизация на сайте

CRUD товаров и CRUD блога защищены `LoginRequiredMixin`. `LOGIN_URL` указывает на **`catalog:login`** (`/accounts/login/`). Новые пользователи регистрируются на `/accounts/register/`; после регистрации выполняется вход без отдельного шага. Админка (`/admin/`) остаётся отдельным интерфейсом; права суперпользователя и обычного пользователя различаются стандартно для Django.

## Шаблоны и статика

- **Базовый шаблон:** `catalog/templates/catalog/base.html` — сайдбар, меню, переключение темы, вывод flash-сообщений.
