# Архитектура

## Приложения

| Приложение | Назначение |
|------------|------------|
| `config` | Настройки проекта, корневые URL, WSGI, валидация изображений, список запрещённых слов |
| `catalog` | Главная, каталог, категории, карточка товара, CRUD товаров, контакты, сервисный слой |
| `blog` | Список и детали постов, CRUD записей блога |
| `users` | Модель `User` (вход по email), регистрация, вход, выход, профиль |

## Маршруты верхнего уровня (`config/urls.py`)

- `/admin/` — админка Django
- `/accounts/` — `users.urls` (регистрация, вход, выход, профиль)
- `` (пустой префикс) — `catalog.urls` (главная, товары, каталог, категории, контакты)
- `/blogs/` — `blog.urls`

## Модели

### catalog

- **Category** — наименование, описание.
- **Product** — наименование, описание, изображение, категория (FK), цена, `is_published`, `owner` (FK на User). Кастомное право `can_unpublish_product`.
- **Contact** — имя, email, сообщение (обратная связь).

### blog

- **BlogPost** — заголовок, содержимое, превью, `is_published`, `view_count`, `author` (FK на User).

### users

- **User** (`AbstractUser`) — `USERNAME_FIELD = email`, аватар, телефон, страна.

## Разграничение прав

### Группы

| Группа | Права |
|--------|-------|
| Модератор продуктов | `catalog.can_unpublish_product`, `catalog.delete_product` |
| Контент-менеджер | `blog.add_blogpost`, `blog.change_blogpost`, `blog.delete_blogpost`, `blog.view_blogpost` |

Создаются командой `manage.py setup_catalog_groups`.

### Логика доступа

- **Каталог:** создание — любой авторизованный (owner = текущий пользователь); редактирование — только владелец (`ProductOwnerRequiredMixin`); удаление — владелец или модератор; публикация/снятие — только модератор.
- **Карточка товара:** опубликованные доступны всем; черновики — владельцу и модераторам; остальным — 404.
- **Управление товарами:** владелец видит свои, модератор — все.
- **Блог:** CRUD — `PermissionRequiredMixin` (группа «Контент-менеджер»); обычный пользователь получает 403.
- **Черновики блога:** `PostDetailView` фильтрует `is_published=True`; неопубликованные — 404.

## Сервисный слой

`catalog/services.py` — бизнес-логика, вынесенная из представлений:

- **`get_products_by_category(category_id)`** — возвращает опубликованные товары категории. При включённом кеше результат сохраняется в Redis на 15 минут.

## Кеширование

Управляется переменной `CACHE_ENABLED` в `.env`. При `True` подключается `django.core.cache.backends.redis.RedisCache`.

| Что | Механизм | Таймаут |
|-----|----------|---------|
| Карточка товара | `@cache_page` на `ProductDetailView` | 15 мин |
| Список товаров в категории | `cache.get` / `cache.set` в `get_products_by_category` | 15 мин |

## Пользователь и авторизация

- `AUTH_USER_MODEL = users.User`, вход по **email**.
- `LOGIN_URL` → `users:login` (`/accounts/login/`).
- `LOGIN_REDIRECT_URL`, `LOGOUT_REDIRECT_URL` → главная каталога.

## Медиа и статика

- Загрузки: `MEDIA_ROOT` (аватары, фото товаров, превью блога). Валидация: JPEG/PNG, до 5 МБ.
- В `DEBUG=True` медиа отдаёт Django. В продакшене — через веб-сервер.
- `media/` в `.gitignore` — загрузки пользователей не попадают в git.

## Логирование

- `catalog/views.py` пишет информацию о последних товарах в `logs/catalog_views.log`.
- Каталог `logs/` в `.gitignore`.
- Персональные данные (email) не логируются.
