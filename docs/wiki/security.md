# Безопасность

Аудит на основе ревью кода, `config/settings.py`, представлений и шаблонов. Проект учебный — часть мер применима только к продакшену.

## Оставшиеся риски

### 1. Регистрация открыта для всех

Нет подтверждения email, капчи, лимитов. Для публичного сервиса — верификация почты, rate limiting, ручное одобрение.

### 2. Нет ограничения частоты запросов

Подбор паролей к `/accounts/login/` не ограничен на уровне приложения. В продакшене: `django-axes`, fail2ban, WAF или rate limit на reverse proxy.

### 3. HTTPS и secure cookies

Не заданы `SECURE_SSL_REDIRECT`, `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`, `SECURE_HSTS_SECONDS`. Для локальной разработки нормально; при деплое с HTTPS — обязательно включить.

### 4. Redis без аутентификации

URL по умолчанию `redis://127.0.0.1:6379/1` без пароля. Безопасно если Redis слушает только localhost. При сетевом доступе — настроить `requirepass`.

### 5. Заголовки безопасности

Нет CSP (Content-Security-Policy), `Permissions-Policy`. Для жёсткой политики — `django-csp` или заголовки на nginx/Cloudflare.

### 6. SMTP

Пароль почты в `.env`. Файл не попадает в git, но при компрометации сервера секреты утекут. Ограничить права на хосте, ротировать пароли.

### 7. SQLite в файле

При использовании SQLite файл БД должен быть недоступен для скачивания через веб-сервер.

## Чеклист перед деплоем

- [ ] `DEBUG=False`, `ALLOWED_HOSTS` — только ваши домены
- [ ] Уникальный длинный `SECRET_KEY` из переменных окружения
- [ ] PostgreSQL, бэкапы
- [ ] HTTPS за reverse proxy; включить `SECURE_*` и secure cookies
- [ ] Раздача `media/` и `static/` без листинга каталогов
- [ ] Rate limiting на `/accounts/login/` и регистрацию
- [ ] Актуальные зависимости (`poetry update`, проверка уязвимостей)
- [ ] Защита админки (сильные пароли, IP allowlist)
- [ ] Redis с `requirepass` при сетевом доступе

## Итог

Для **локальной учёбы** уровень безопасности хороший: CSRF, пароли, ORM, валидация загрузок, разграничение прав, фильтрация черновиков, защита `.env`, отсутствие PII в логах. Для **реального хостинга** — закрыть пункты из раздела «Оставшиеся риски» и пройти чеклист.
